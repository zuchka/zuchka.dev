remove-markdown

Strip Markdown stuff from text.

A small npm package, ~50 lines of regex. I wrote it in 2015 and never imagined it would still be running a decade later. It is, on a lot of machines.

Install

npm install remove-markdown

Then:

const removeMd = require('remove-markdown');

const md = `## My Heading

Some **bold** text and a [link](https://example.com).`;

console.log(removeMd(md));
// "My Heading\n\nSome bold text and a link."

Options:

removeMd(md, {
  stripListLeaders: true,    // strip bullet/numbered list markers
  listUnicodeChar: ' ',     // or replace with a unicode char
  gfm: true,                  // GitHub-flavored markdown extensions
  useImgAltText: true         // keep image alt text vs. removing the whole image
});

Why

The use case is dumb-simple: you have Markdown somewhere — a blog post, a comment, a README — and you want plain text out. For an SEO description. For a search index. For a tweet. For a notification body. Anywhere a renderer isn't going to run.

You could pull in a full Markdown parser, build the AST, and walk it. Or you could run a few dozen regex substitutions and call it a day. remove-markdown is the second thing.

It's not a Markdown parser. It doesn't understand grammar. It just deletes the syntactic sugar. That's the whole pitch — and it's why it's 50 lines instead of 5,000.

What downloads it

Hard to know exactly. The npm dependency graph shows hundreds of packages depend on it directly, and many more pull it in transitively. Some of the more visible ones over the years:

  • Static site generators and CMSes — generating plain-text excerpts for OG tags, RSS descriptions, search indexes.
  • Notification pipelines — turning a Markdown comment into a push body, an email subject line, a Slack fallback.
  • Editor tooling — word-counts, readability scores, anything that wants to ignore the syntax and look at the prose.

If you've ever copy-pasted a sentence out of a CMS preview and wondered why the asterisks were gone — there's a non-zero chance this thing did it.

Maintenance philosophy

The package is in finished mode. It does what it says. Most of the recent activity is dependency-of-dependency security bumps and the occasional regex edge case that someone in production hit before I did.

When something breaks, I fix it. When someone opens a feature request that would expand the scope, I usually decline — there are full Markdown parsers for that. The library's value is its smallness.
