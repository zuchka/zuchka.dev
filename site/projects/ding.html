DING

Persistent watches. Durable alerts.

Watch an API, run a local check, or push JSON from your software. Ding remembers what it saw, explains why a condition fired, and keeps trying to deliver the alert.

Status

Ding is active again. The persistent watch runtime, local Console, and native macOS notifications are in the public v0.15.2 release. Ding Cloud and the ChatGPT and Claude plugin packages are being qualified separately.

Get started

On macOS or Linux, install Ding with Homebrew. Setup guides you through background startup and opens the Console, where you can create a first watch and test an alert. Personal local use needs no account or model key. 

brew install ding-labs/tap/ding
ding setup
ding ui

Start with the local setup guide, or browse the examples before installing.

What it does

  • Observe — poll an HTTP endpoint, run an explicit local command, or accept authenticated JSON.
  • Evaluate — use versioned YAML to detect repeated failures, changed values, missing data, or new provider events.
  • Remember — keep incident state, event evidence, and pending deliveries in SQLite across restarts.
  • Deliver — use the Console, desktop notifications, webhooks, Slack, or Discord, with durable retries for remote delivery.
  • Investigate — inspect watches, events, and delivery attempts in the local Console or through the CLI and API. A local MCP adapter lets agents work with the same watch definitions.

Why I built it

An alert is only useful if you can tell what happened and whether anyone received it. Ding connects the observation, the decision, the event, and the delivery attempt. It keeps watching after you close the terminal, and it gives both people and coding agents a way to inspect the same evidence.

One watch, four connected stages: observe → evaluate → record → deliver. The daemon does the checking; it does not call a model on each observation.
